# SpinPoint

[Відкрити сайт на GitHub Pages](https://dimarger.github.io/spinpoint/) · [Telegram @maybewritee](https://t.me/maybewritee)

Viber тимчасово недоступний. Публічна версія призначена для показу магазинам; деталі розміщення — у DEPLOYMENT.md. Реквізити та комерційні умови ще потребують заповнення, але Telegram уже налаштований.

Повноцінний статичний магазин інвентарю для настільного тенісу. Український інтерфейс, UAH, React + TypeScript + Vite, Tailwind CSS, React Router, Zustand, Motion та Lucide. Сервер, платний хостинг і ключі API для роботи не потрібні.

**Статус:** функціональне застосування з каталогом 80 товарних позицій: 50 накладок, 16 основ і 14 товарів для догляду, зберігання та захисту. Фотографії мають прозорий фон. Роздрібні ціни встановлені за прайсом власника від 15.10.2026; наявність обраного виконання й доставку потрібно підтвердити. Telegram продавця налаштований; реквізити та правові умови ще потребують заповнення. Сайт не приймає оплату та не повідомляє про прийняте замовлення без підтвердження менеджером.

## Запуск

Потрібні Node.js 24 LTS і npm.

У Windows можна двічі натиснути `START.cmd`. Перший запуск встановить залежності, запустить магазин і відкриє браузер. Залишайте вікно запуску відкритим, поки користуєтеся локальним сайтом. Для ручного запуску:

```sh
npm ci
npm run dev
```

Відкрийте адресу, надруковану Vite. Для зібраної версії:

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

Не відкривайте `dist/index.html` через `file://`: модулі потрібно обслуговувати HTTP-сервером. Якщо локальний npm на Windows має помилковий `script-shell`, використайте `npm --script-shell="C:\Windows\System32\cmd.exe" run dev`. Це виправлення лише для такої конфігурації комп’ютера; у GitHub Actions воно не потрібне.

## Що реалізовано

- Головна: категорії, добірка популярного, новинки, пропозиція збірки, порядок замовлення, інформація про магазин, FAQ та контакти.
- 80 товарних позицій у 6 заповнених категоріях; категорія готових ракеток збережена для подальшого наповнення.
- Пошук за назвою й брендом, кілька категорій і брендів, діапазон цін, сортування, новинки, сітка / список, кількість результатів, скидання. Стан фільтрів записаний у URL.
- Сторінка кожного товару, галерея, варіанти, кількість, кошик, обране, пов’язані товари та підготовка запиту.
- Збереження кошика, варіантів, обраного й теми в localStorage; перевірка відновлених даних.
- Конструктор: основа → чорна накладка → червона накладка → стрічка та збірка → підсумок. Групове додавання компонентів у кошик.
- Оформлення запиту з мінімальними контактними даними, Telegram / Viber, копіювання, видимий текст і резервне завантаження `.txt`.
- B2B-сторінка та формування запиту комерційної пропозиції.
- Доставка, оплата, передзамовлення, повернення, приватність, контакти й інформація про магазин. Незатверджені умови прямо позначені.
- Локальний редактор: товари, ціни, статуси, варіанти, характеристики, фото, імпорт / експорт JSON, перевірка схеми, відновлення початкових даних.
- Мобільне меню на нативному `<dialog>` із фокусом та Escape, світла / темна тема, повідомлення, порожні стани, 404, обробка помилок, lazy loading сторінок, зображень і reduced motion.

## Архітектура

```text
src/
  assets/               примітки про медіа
  components/           Layout, ProductArt, Common, OrderComposer, ErrorBoundary
  config/site.ts        назва, контакти, умови збірки, дані продавця
  data/catalog.ts       початковий публічний каталог
  features/catalog/     контракти CatalogRepository / OrderRepository
  hooks/useMeta.ts      title, description та Open Graph
  pages/                сторінки магазину
  stores/shop.ts        Zustand + localStorage
  styles/index.css      дизайн, адаптивність, теми
  types/catalog.ts      типи та Zod-схема імпорту
  utils/                фільтри, підрахунки, формування повідомлень і тести
public/images/          локальні зображення
.github/workflows/      перевірки та GitHub Pages
```

Логіка цін, повідомлень та фільтрації відокремлена від сторінок. Особисті дані форми залишаються в пам’яті сторінки: вони не записуються в localStorage, базу чи репозиторій. Натискання кнопок месенджера може передати текст відповідному сервісу; користувач бачить це до переходу.

## Єдина конфігурація

Редагуйте `src/config/site.ts`:

```ts
contacts: {
  telegramUsername: '', // власний username менеджера без @
  viberPhone: '',       // міжнародний формат, наприклад +380…
  email: '',
  phone: '',
},
assembly: { enabled: true, fee: 150, freeFrom: 5000, label: '...' },
```

`name` керує назвою в логотипі, заголовках, інформаційних сторінках і метаданих HTML (Vite-плагін підставляє її під час build). Під час ребрендингу за потреби змініть favicon і зміст текстів. `demo` — глобальне позначення тестового режиму; кожен товар додатково має власний прапорець `demo`. Вимикайте їх лише після перевірки даних.

Умови безкоштовної збірки застосовуються до загальної вартості товарів замовлення; послуга в кошику є запитом на збірку всього замовлення. Кількість ракеток, обсяг робіт і фінальну ціну підтверджує менеджер. Автоматичного висновку про професійну сумісність немає: перевіряється лише вибір основи та двох накладок різних кольорів.

## Каталог і фотографії

Каталог містить реальні моделі й варіанти з відкритих товарних карток, перевірених 14.10.2026. Роздрібні ціни оновлені за прайсом власника від 15.10.2026 і не виводяться з колишнього розрахунку націнки. Вони не підтверджують прибуток 70 грн за одиницю. Історія зміни та зіставлення моделей — у PRICE_AUDIT.md; окремий приватний PROFIT_AUDIT.md містить граничну повну собівартість усіх 80 позицій. Наявність конкретного виконання, строки й комплектацію узгоджують перед оплатою. Відкриття картки не підтверджує якість фізичного зразка чи автентичність партії. Показники ITTF і рекламні оцінки швидкості не скопійовані як перевірені характеристики.

У `src/data/products.json` міститься публічний каталог. `src/data/catalog.ts` перевіряє його через Zod. У ньому немає закупочних цін чи приватних посилань. Для редагування кожного товару можна скористатися редактором `/#/catalog-editor` і експортувати JSON. Розрахунок закупки зберігається окремо від цієї папки й не включений у сайт або його ZIP.

Локальний редактор не захищений паролем, тому що він не змінює сервер і не має адміністративних повноважень. Кнопка «Застосувати локально» впливає лише на поточний браузер і origin; очищення сховища прибере зміни. Для зміни загальнодоступного каталогу:

1. Імпортуйте або відредагуйте товари, перевірте ціни та зображення.
2. Експортуйте каталог і замініть ним `src/data/products.json`.
3. `src/data/catalog.ts` уже перевіряє JSON. Якщо використовуєте іншу назву, змініть відповідний імпорт:

```ts
import rawCatalog from './products.json';
import { catalogSchema } from '../types/catalog';
export const initialCatalog = catalogSchema.parse(rawCatalog);
```

4. Виконайте перевірки, перегляньте сайт і зробіть commit / push. Тести поточного набору в `shop.test.ts` прив’язані до 80 моделей; після заміни асортименту оновіть відповідні очікування.
5. Для цього оновлення старий локальний каталог версії 1 автоматично отримує нові ціни відомих моделей під час міграції сховища на версію 2. Кошик та інші дані зберігаються. Наступні локальні правки редактора працюють як раніше; для повного скидання локального каталогу виберіть «Відновити».

Схема: унікальний slug `id`, назва, бренд, категорія, невід’ємна роздрібна `price`, `status` (`preorder`, `available`, `unavailable`), `leadTime`, `description`, масив `variants`, словник `specs`, прапорці `popular`, `isNew`, `demo`, дата `addedAt`, `image`. `priceEstimated: true` позначає орієнтовну ціну; для поточного прайсу власника встановлено false. Цей прапорець не підтверджує закупочну собівартість. Додаткові фото — масив `gallery` (до 8). Для торцевої стрічки вкажіть `accessoryType: 'tape'`; тоді вона доступна в конструкторі.

`image` / `gallery`: HTTPS-адреса або шлях `images/model.webp`. Локальні файли покладіть у `public/images/`. Краще використовувати власні оптимізовані WebP з дозволом на публікацію. Зовнішні фото залежать від чужого сервера й можуть перестати працювати. Якщо фото відсутнє або не завантажилося, відображається схематична ілюстрація категорії. Вона не видається за фото конкретної моделі.

Не додавайте внутрішні закупочні ціни, приватні посилання на постачальників, ключі API чи дані покупців. Імпортована схема відкидає невідомі поля, але автор репозиторію все одно має перевіряти публічні файли перед commit.

## Telegram і Viber

З указаним username використовується `https://t.me/<username>?text=...`; без контакту — `https://t.me/share/url?url=<адреса магазину>&text=...`, де користувач сам обирає одержувача. Наявність чернетки залежить від клієнта, тому текст завжди доступний для копіювання.

Для номера Viber відкривається `viber://chat?number=...`. Текст у такому чаті потрібно вставити вручну. Без номера використовується `viber://forward?text=...`. Для запитів понад 200 символів share-посилання містить короткий вступ: повний текст копіюється для ручного вставлення. Для відкриття потрібен встановлений клієнт; браузер не може гарантувати запуск застосунку. Резерв — ручне копіювання або `.txt`.

Для Telegram-запитів довше 3 500 символів також використовується короткий вступ і підказка надіслати повний текст частинами або файлом. Схеми перевірено за офіційною документацією [Telegram](https://core.telegram.org/api/links#public-username-links) і [Viber Share Button](https://developers.viber.com/docs/tools/share-button/).

Жодна кнопка не надсилає повідомлення автоматично. Немає фіктивного номера замовлення, статусу «прийнято» або списання коштів. Менеджер підтверджує умови в реальному листуванні. У тестовому режимі замовлення містить явну позначку тестового запиту.

## GitHub Pages

Workflow уже в `.github/workflows/deploy.yml`. Потрібен ваш GitHub-репозиторій; у цьому завданні його не створювали й віддалений деплой не запускали.

1. Завантажте вміст цієї папки в корінь репозиторію з гілкою `main`, разом із `.github`, `package-lock.json` та конфігураціями. Не завантажуйте `node_modules` або контактні дані покупців.
2. У GitHub: Settings → Pages → Source → GitHub Actions.
3. Push у `main` запускає встановлення, typecheck, lint, тести, build і deploy. Також можна запустити workflow вручну.
4. Перевірте адресу зі сторінки workflow.

У Vite `base: './'`, тому ресурси працюють і в `https://user.github.io/repo/`, і в корені власного домену. За потреби встановіть `VITE_BASE_PATH=/repo/` під час build. Використано `HashRouter`: приклад `https://user.github.io/repo/#/product/butterfly-viscaria`. Після оновлення сторінки сервер запитує той самий `index.html`, тому fallback-сервер і rewrite не потрібні. Невідома hash-адреса відображає сторінку 404 усередині застосування.

Власний домен: налаштуйте DNS відповідно до інструкцій GitHub Pages і вкажіть домен у Settings → Pages. Якщо керуєте файлом `CNAME`, додайте його в `public/CNAME` з вашим фактичним доменом. Фіктивного домену в проєкті немає.

Застосування оновлює title / description / OG у браузері. Через hash-маршрути та відсутність серверного рендерингу пошукові роботи й прев’ю месенджерів можуть бачити лише загальні метадані `index.html`. Для повного SEO окремих товарів наступним етапом потрібна генерація HTML для кожної сторінки з окремими метаданими; цього не підмінено неправдивою обіцянкою. `og:image`, canonical і sitemap варто додати після визначення реального домену. Зображення головної оптимізоване приблизно до 112 КіБ.

## Підготовка Supabase

Контракти адаптерів: `src/features/catalog/repository.ts`. Наразі Zustand читає початковий TypeScript-каталог або локальне перевизначення. Контракт не виконує фіктивних запитів; живий Supabase не підключений.

Окремий етап інтеграції описаний у `SUPABASE.md`: публічний каталог, авторизоване редагування, RLS, медіа, заявки, міграція й політика персональних даних. Supabase потребує реального проєкту й погоджених правил доступу.
